# rafaelgorski.com

A public register of positions on launching and scaling AI. Each position is one
sentence with what is at stake, the evidence, what would change it and a revisit
date; on that date it is marked held or revised, in public. A curated library of
sources, filed by stage, is the evidence base behind the positions.

Plain static HTML, generated by a zero-dependency Node script and served by
GitHub Pages. No JavaScript on any page except one inline line in `404.html`; no
tracking; fonts are self-hosted.

## Layout

```
content/
  log.json                     the register: positions and titles in preparation
  log/<id>.html                full note behind each position (trusted HTML)
  library.json                 curated sources (owned by the content workstream)
  library.sample.json          illustrative stand-in, used only while library.json is absent
  stages.json                  the six stages (optional; the fixed contract is built in)
static/                        copied as-is: assets/site.css, fonts, favicon (and CNAME later)
scripts/build.mjs              content/ + static/ → _site/
scripts/check-links.mjs        fails if any internal link or #fragment does not resolve
.github/workflows/pages.yml    builds, link-checks and deploys on push to main, and weekly
PRODUCT.md / DESIGN.md         product and design records
```

Generated pages: `/` (the register), `/log/<slug>/` (one per position),
`/library/` and `/library/<stage>/` (one static page per stage, so filtering
works without JavaScript), `/about/`, `/404.html`, and a redirect from the old
`/notes/agentic-observability/` address.

All internal links are relative, so the site works both at
`https://rafaelgorski.github.io/rafaelgorski.com/` and at the root of a custom domain.

## Build and preview locally

Requires Node 18 or later. No `npm install`.

```
node scripts/build.mjs           # writes _site/; BUILD_DATE=YYYY-MM-DD pins the "as of" date
node scripts/check-links.mjs     # verifies every internal link
python -m http.server 8000 --directory _site
```

## Logging a position

1. Add an entry to `content/log.json` with the next number (`GN-0002`), a one-sentence
   `position`, `stakes`, `evidence`, `change` (what would change it), `logged` and
   `revisit` months (`YYYY-MM`), `status: "open"`, and its `stages`.
2. Put the full note in `content/log/<id>.html`. Use `<h3 id="s1">` section headings;
   the build lists them in the entry's contents.
3. List the library sources it rests on in `library` (ids) or `libraryUrls` (URL prefixes).

## Recording a verdict

Never edit a position in place. At the revisit, set `status` to `held` or `revised`
and append to `verdicts`:

```json
{ "date": "2027-04", "verdict": "revised", "previous": "the original sentence", "note": "why" }
```

For a revision, put the new sentence in `position`; the old one is shown struck
through above it. A position left `open` past its revisit month is shown as
overdue automatically on the next build (the workflow rebuilds weekly).

## Publish

1. In **Settings → Pages**, set **Source** to **GitHub Actions** (one time).
2. Push to `main`. The workflow builds `_site/`, checks links and deploys.

## Moving the domain

When ready to serve from `rafaelgorski.com`:

1. Add a file `static/CNAME` containing `rafaelgorski.com`.
2. In **Settings → Pages → Custom domain**, enter `rafaelgorski.com` and enable **Enforce HTTPS**.
3. At the DNS provider, point the apex `A` records to GitHub Pages
   (`185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`) and `www` as a
   `CNAME` to `rafaelgorski.github.io`.
